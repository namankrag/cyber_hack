# AgentShield — Frontend

The AgentShield web app. It contains two surfaces built on the same Next.js
project:

- **Public marketing site** (`/`) — product story, architecture, documentation,
  the sandboxed Decision Lab and the demo-request form.
- **Operator workspace** (`/workspace/*`) — a live control plane for the
  AgentShield gateway: decisions, enforcement, approvals, policy, threats,
  red-team runs, the RAG corpus and audit evidence.

The workspace never invents data. Every metric, decision and record comes from
the FastAPI gateway through the server-side `/api` proxy. Loading, empty,
stale, disconnected and error states are first-class UI states.

## Quick start

```bash
cd web
cp .env.example .env.local     # optional if the gateway is on the default URL
npm install
npm run dev                    # http://127.0.0.1:3000
```

Start the gateway separately (from the repository root):

```bash
.venv/bin/uvicorn agentshield.gateway.app:app --port 8000 --host 127.0.0.1
```

### Environment variables

All variables are **server-side only**. Never rename them with a
`NEXT_PUBLIC_` prefix.

| Variable | Default | Purpose |
| --- | --- | --- |
| `AGENTSHIELD_API_URL` | `http://127.0.0.1:8000` | Gateway base URL used by the proxy |
| `AGENTSHIELD_API_KEY` | empty | Read key forwarded as `X-API-Key` |
| `AGENTSHIELD_ADMIN_KEY` | empty | Admin key for admin/approval/red-team routes |
| `ADMIN_PASSWORD` | empty | Browser operator password; verified server-side, issues an httpOnly session cookie |

If the backend has `AGENTSHIELD_API_KEY` / `AGENTSHIELD_ADMIN_KEY` set, mirror
the same values here. They stay in the Next.js server process.

## Request flow

```text
Browser (client component)
   │  fetch("/api/v1/audit?limit=50")
   ▼
Next.js route handler  src/app/api/[...path]/route.ts
   │  allowlist → choose read/admin key → fetch(GATEWAY + path)
   ▼
FastAPI gateway  http://127.0.0.1:8000
```

### Proxy rules (`src/app/api/[...path]/route.ts`)

- **Allowlist:** an exact method + route table (see `matchRoute` in
  `src/app/api/_lib/proxy-auth.ts`) — no prefix matching. Anything else
  returns `404` without touching the gateway. `POST /v1/approvals/{call_id}`
  is the only dynamic entry; `.`, `..` and encoded slashes (`%2F`, `%5C`)
  are rejected with `404`.
- **Admin session:** `v1/admin*`, `v1/approvals*` and `v1/redteam*` require
  a valid session cookie, else `401`. Sign in via `POST /api/admin/login`
  with the server-side `ADMIN_PASSWORD`; the proxy issues an httpOnly,
  `SameSite=Lax` signed cookie (`GET /api/admin/session` reports state,
  `POST /api/admin/logout` clears it). The admin key is attached as
  `X-API-Key` server-side only and is never sent to the browser.
- **Key selection:** privileged routes use `AGENTSHIELD_ADMIN_KEY` (falling
  back to the read key); everything else uses `AGENTSHIELD_API_KEY`.
- **CSRF:** non-`GET` requests with a present `Origin`/`Referer` must match
  the proxy origin, else `403`. Mutations carrying a body must declare
  `Content-Type: application/json`, else `415`.
- **Body cap:** request bodies over 64KB are rejected with `413` (declared
  size first, then measured bytes).
- **Query forwarding:** every incoming search param is copied to the upstream
  URL.
- **No caching:** requests use `cache: "no-store"` and responses are returned
  with `Cache-Control: no-store`.
- **Timeout:** the upstream request aborts after 12 seconds and returns a
  structured `502` with a `detail` and `hint` instead of a raw network error.
- **Methods:** `GET`, `POST`, `PUT`, `DELETE` share one forwarding path;
  only allowlisted combinations are forwarded.

### Client layer (`src/lib/api/client.ts`)

- `apiGet<T>()` / `apiPost<T>()` always talk to `/api`, never directly to the
  gateway.
- A 15-second client timeout aborts the request.
- Non-2xx responses are converted to `ApiError` with `{ detail, hint }` parsed
  from the gateway body.
- Invalid JSON becomes a `parse` failure rather than a crash.
- `buildQuery()` skips empty values; `callPath()` safely encodes a call id.

### Error taxonomy (`src/lib/api/errors.ts`)

| Kind | Meaning |
| --- | --- |
| `network` | Proxy could not reach the gateway |
| `timeout` | No response before the deadline |
| `http` | Gateway returned a non-2xx status (401/403/404/409/5xx have dedicated copy) |
| `parse` | Response was not valid JSON |
| `unknown` | Anything else |

`failureTitle()` and `failureHint()` translate these into operator-facing
messages: `401` maps to the administrator-login message (sign in on Settings),
while `403`/`502` name the server-side env var to check.

## Live data logic (`useLiveData`)

All workspace polling goes through one hook:

```ts
const audit = useLiveData<AuditResponse>("/v1/audit?limit=50", {
  intervalMs: 15_000,
});
```

Behaviour:

- **Path-keyed snapshots.** A new query never renders the previous query's
  data while loading.
- **Visibility-aware polling.** The interval only fires while the tab is
  visible; becoming visible triggers an immediate refresh.
- **Abort on change/unmount.** In-flight requests are aborted when the path
  changes or the component unmounts.
- **Stale-on-error.** If a later poll fails, the last good snapshot stays on
  screen and `isStale` becomes `true`, so pages can show a stale banner instead
  of blanking out.
- **Manual refresh.** `refresh()` is exposed for page-level refresh buttons and
  post-action refetches.
- **Shape:** `{ data, failure, isLoading, isRefreshing, isStale, lastUpdated,
  refresh }`.

## Workspace shell logic

`src/components/workspace/workspace-shell.tsx` owns navigation, header and
global menus; page content is rendered as children inside `<main>`.

- **Navigation source of truth:** `src/components/workspace/nav.ts` defines the
  four groups and every item (label, description, icon, href). The sidebar and
  command palette both read from it.
- **Active item:** `itemIsActive()` compares the pathname; `/workspace` is
  exact-match. Settings uses the URL hash: `#health` is the default and
  `#configuration` activates Configuration.
- **Pending badge:** the shell polls `/v1/approvals?limit=1` every 30 seconds
  and shows the pending count on Approval Center.
- **Gateway/enforcement status:** `/health` (20 s) and `/v1/enforce` (20 s)
  drive the sidebar footer and header badges. Pages that change enforcement
  dispatch `window.dispatchEvent(new Event("agentshield:enforce-changed"))`;
  the shell listens and refreshes `/v1/enforce`.
- **Command palette (`⌘K` / `Ctrl+K`):** navigation only. The dialog mounts only
  while open, so query and selection reset naturally. Escape/backdrop close,
  focus is restored to the trigger, and no gateway search is implied.
- **Time window:** the header shows `TimeWindowControl` only on Overview and
  Analytics. `TimeWindowProvider` (default `24h`) shares the selection with both
  pages; `1h`, `24h`, `7d`, `30d` and `all` map to the `window` query param.
- **User menu:** outside click and Escape close it; links close it on click.
- **Mobile:** below 1080 px the sidebar becomes a drawer with an overlay,
  `aria-expanded`/`aria-controls`, body scroll lock and Escape handling.

- **Tokens:** cream paper `#EAE9E7`, surface `#F8F7F4`, navy `#191D35`, purple

## Honesty and safety rules baked into the UI

- **No fabricated metrics.** Values come from the gateway or render as `—` /
  loading / empty. Charts are drawn from real `series` data.
- **Sample limits are visible.** Metrics and list endpoints are bounded
  (commonly 500 entries); the UI states when a sample cap was reached instead of
  implying a complete history.
- **No invented capabilities.** Policy Manager is explicitly read-only because
  no publish endpoint exists. Approval expiry shows "unknown" when the backend
  returns `null`. Threat categories are labelled as presentation grouping.
- **Destructive actions confirm.** Enforcement changes, approval decisions and
  corpus re-ingest all go through `ConfirmDialog` and surface backend errors
  (including `409`) rather than assuming success.
- **Red-team isolation is stated.** Red Team Lab compares ON/OFF behaviour and
  displays `global_enforcement_unchanged`; it does not silently flip the global
  switch.
- **Secrets stay server-side.** The browser bundle contains no API/admin keys;
  the proxy is the only component that holds them.
- **Reduced motion and keyboard access** are respected throughout (focus
  rings, dialog roles, Escape handling, skip link, labelled controls).

## Marketing-site logic

- `SiteNav` scroll-spies the anchored sections and marks the active link;
  the mobile menu traps nothing but closes on outside click, Escape and link
  selection, returning focus to the trigger.
- `Reveal` uses an `IntersectionObserver`; reduced-motion users see content
  immediately via CSS.
- `DecisionLab` is a scripted, explicitly labelled `SANDBOX` demonstration —
  it is not connected to `POST /v1/check`.
- `DemoForm` builds a `mailto:security@agentshield.dev` request from the form
  fields and tells the visitor to send it. There is no backend demo endpoint.
- The homepage footer links status to the live workspace instead of claiming
  "all systems operational".

## Known limitations (backend-driven)

These are real constraints, not frontend shortcuts:

- No auth/session/RBAC endpoints; admin capability is inferred by probing and
  the dev gateway reports `auth_required: false`.
- No policy publish endpoint, so Policy Manager is read-only.
- No dedicated agents/sessions store; sessions are projected from audit
  metadata and limited to the retained sample.
- No external threat feed; Threat Intelligence shows detector findings only.
- Approval expiry is not populated by the backend (`expired: null`).
- No cursor pagination; endpoints cap `limit` (commonly 500).
- No latency/cost fields in the audit schema, so no timing or cost claims.
- Corpus re-ingest (`POST /v1/admin/reset`) currently returns `500` because
  `chromadb` is missing from the Python environment; the UI surfaces that error.
- Demo requests rely on the visitor's mail client (`mailto:`).

See `../COMPLETION_REPORT.md` for the full implemented / partial / blocked
breakdown.

## Adding a workspace page

1. Add `src/app/workspace/<name>/page.tsx` with `metadata` and a client
   component.
2. Build the client in `src/components/workspace/<name>-client.tsx`; fetch with
   `useLiveData` / `apiGet` / `apiPost` — never call the gateway directly.
3. Add the item to `workspaceNavGroups` in `src/components/workspace/nav.ts`
   (the sidebar and command palette pick it up automatically).
4. Extend `src/lib/api/types.ts` with the response contract.
5. Use the existing primitives (`Card`, `PageHeader`, `StatCard`,
   `DecisionBadge`, `ErrorState`, etc.) and `ws-*` classes so the page inherits
   the design system.
6. Run `npm run typecheck`, `npm run lint` and `npm run build`, then verify the
   route at desktop and 390 px.
